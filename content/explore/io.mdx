## 为什么它很重要

I/O 系统是用户意图与设备、驱动交汇的地方。如果你想要理解文件、磁盘、键盘或者网络，最终都需要掌握 I/O 流水线。

## 思维模型

Windows I/O 是一套路由请求系统：应用发起任务请求，I/O Manager 将请求封装，分层驱动协同完成该请求。

## 工作原理

1.  1用户态 API 调用进入内核，转换为 I/O request packet (IRP)。
2.  2I/O Manager 将 IRP 下发至一个或多个设备栈。
3.  3驱动根据自身角色，处理、转换、转发或者完成该请求。

## 关键术语

IRP

I/O Request Packet；用于表示一次 I/O 操作的核心内核结构体。

Driver stack

有序驱动集合，协同处理设备请求。

Device object

I/O 系统内部代表一个设备实例的内核对象。

## 应用程序打开文件

一次简单的文件打开操作，在用户态看起来只是一次 API 调用，但 Windows 会将其转换为 I/O 请求，该请求需要穿越多层组件，之后文件系统或设备才会响应。

## 常见误区

驱动并不总是请求的最终持有者。很多请求在完成前会经过多个驱动。
